--- step 1: user says: 帮我查一下 Bun 1.4 在 Linux 上用 bun build --compile 有哪些坑，整理成一页文档
  [partner message] 这是一份按 Linux 整理的一页速查，来自 GitHub issue 和发版说明。它不是 Bun 官方的已知问题清单，其中不少是未经核实的报告，用之前请先看一下各条的当前状态。

**Bun 1.4 用 `bun build --compile` 在 Linux 上的坑**

1. **标准输入可能读到多余的 NUL 字节。** 1.4.0 和 1.4.2 生成的 Linux x64 程序，用 `Bun.stdin.stream()` 按换行读取时会多出一个 NUL，1.3.14 没有这个问题。有人的临时办法是 Linux 构建先用 1.3.14。这个问题目前看是未解决的（[#42509](https://github.com/oven-sh/bun/issues/42509)）。
2. **运行时从磁盘加载的模块，会忽略 package.json 的 `exports` 和 `main`。** 1.4.2 和 1.4.3 有报告（[#46412](https://github.com/oven-sh/bun/issues/46412)）。
3. **外部包里的 CJS `require` 可能失败。** 1.4.2 有报告，1.3.2 正常（[#42368](https://github.com/oven-sh/bun/issues/42368)），这条已被关闭为不会修。
4. **原生依赖要装齐。** 报告显示，构建需要同时装 glibc 和 musl 两套原生包（[opentui #1909](https://github.com/anomalyco/opentui/issues/1909)）。1.4.4 起 Bun 会读取 libc 字段，所以只需装一套。
5. **堆栈追踪可能停在中间生成的文件上。** 如果输入已有 source map，堆栈就不会映射回原始源码（[#45372](https://github.com/oven-sh/bun/issues/45372)）。
6. **1.4 行为变化：** 编译出的程序不再自动加载工作目录里的 tsconfig.json 和 package.json。要恢复需加 `--compile-autoload-tsconfig` 或 `--compile-autoload-package-json`（[1.4 破坏性变更清单](https://github.com/oven-sh/bun/issues/28792)）。
7. **动态 `import()` / `require()` 只能加载编进去的代码。** 磁盘上有但没编进去的文件会加载失败，除非加 `--aot-allow-code-from-disk`（[官方排错文档](https://bun.com/docs/compiler/troubleshooting)）。
8. **原生插件（.node）要看清楚。** 资料互相矛盾：有的说 1.0.23 起可以嵌入，有的说不会嵌入，操作系统的动态链接器得从磁盘加载。最稳的做法是静态写 `require("./x.node")`，动态路径加载则要让文件跟在程序旁边。运行时 `cc()` 编 C 代码不行，要在构建时编好再用 `dlopen`。
9. **WSL1 可能报 ENOEXEC。** 旧报告（[#29963](https://github.com/oven-sh/bun/issues/29963)），我没查到它现在是否还在。
10. **已在后续小版本修掉的：** 1.4.1 修了 UPX 压缩后报 `Invalid character: '\0'`，并让超过 4 GiB 的嵌入文件在构建时就报错，不再拖到启动时才崩。1.4.3 修了在编译后的程序里再次编译（`BUN_BE_BUN=1` 或 `Bun.build({ compile })`）生成的程序启动即崩的问题，这个回归从 1.3.14 开始。

**给你的建议**
- 用 1.4.3 以上版本，并在目标 Linux 环境里实际跑一遍，别只在 Mac 上测。
- 有标准输入的程序，先用 1.3.14 或者验证 #42509 是否已修。
- 所有动态加载（包括原生插件）都明确列出来，逐一测试。
